## Git-Recovery (vor dem Routine-Commit)

Vor dem Commit zeigte das lokale Repo einen kaputten Zustand:

- **Null Commits**, alle 197 Dateien als initialer Add gestaged → lokale `main` „ungeboren",
  obwohl `origin/main` (`7d5a4d3`) die volle Historie trägt.
- Verwaister `.git/refs/heads/main.lock` (vom abgebrochenen Session-32-Vorgang) + altes Finder-
  Duplikat `.git/index 2.lock` blockierten Ref-Updates.

**Non-destruktive Reparatur (kein `--force`, keine Datenverluste):**

1. Read-only-Diagnose: `git fetch origin` + `git diff --stat origin/main` → lokaler Baum **inhaltlich
   identisch** mit `origin/main`, nur die bearbeiteten Dateien weichen ab → das `.git` hatte bloß
   HEAD/Index verloren.
2. `pgrep` bestätigt: kein git-Prozess aktiv → beide `.lock`-Files entfernt.
3. `git update-ref refs/heads/main origin/main` hängt die lokale `main` an die echte Historie an,
   Working Tree unberührt.
4. Danach `git status` = genau die 6 bearbeiteten Dateien → Commit + Push als sauberer Fast-Forward.

Gleiche Fehlerklasse wie der `index.lock`-Crash 2026-05-10. Dokumentiert in [[../PROBLEME#✅ Gelöst]].
