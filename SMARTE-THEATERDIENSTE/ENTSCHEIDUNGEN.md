| ADR-29 | 2026-04-27  | **`revalidatePath('/[locale]/<route>', 'page')`** statt `revalidateTag` im Webhook | Tag-basierte Invalidation würde `cacheComponents: true` + `'use cache'` an jedem Query-Helper voraussetzen. `revalidatePath` arbeitet mit den Route-Files (Pattern matched beide Locales in einem Aufruf) und benötigt nur `export const revalidate = 60` an den Pages. | ADR-31 | 2026-04-30  | **Public-Read-Queries über `getSupabaseAnon()`**, nicht den Cookie-bewussten Server-Client | `getSupabaseServer()` ruft `cookies()` und triggert damit in Next.js 16 einen Dynamic-Switch — Pages werden zu ƒ statt ●. | ADR-32 | 2026-04-30  | **Revalidate per `pg_net`-Trigger direkt in Supabase Cloud** statt Studio-Hook | Die Supabase-Studio-Webhook-Funktion ist intern ebenfalls `pg_net`. | ADR-33 | 2026-04-30  | **`.vercelignore` schützt CLI-Deployments vor lokalen Env-/Tooling-Dateien** | Der erste CLI-Deploy erkannte lokale `.env`-Dateien im Upload-Kontext. `.vercelignore` schließt `.env*`, `.vercel/`, `.claude/`, `.next/`, `node_modules/`, Obsidian-Config und `supabase/.temp/` aus. | ADR-34 | 2026-05-01  | **Wikimedia-Locator-Karte als statisches SVG + lineares Equirectangular-Mapping** für Partner-Karte | `Germany_location_map.svg` (NordNordWest, public domain, 463 KB) liegt unter `public/maps/germany.svg`. Bounding-Box `N=55.1°, S=47.2°, W=5.5°, E=15.5°`. Hotspots werden via simpler Linear-Interpolation `x=(lng-W)/(E-W)`, `y=(N-lat)/(N-S)` als Prozent positioniert — der "150% N/S-Stretch" der Karte ist im Asset bereits eingebacken, das lineare Mapping trifft die Position korrekt. Kein Leaflet, kein D3-Geo, kein TopoJSON; passt zur bestehenden Architektur (siehe ADR-11). Hotspots sind ein absolut positioniertes `<button>`-Layer über dem `<img>`, GSAP animiert nur den Pulse-Ring. |
| ADR-35 | 2026-05-06  | **SEO-Layer M8: Layout-Default + per-Page `pageMetadata`-Helper, Sitemap auf App-Ebene, lokalisiertes OG-Image, Hex-Akzentfarbe in `ImageResponse`** | Layout setzt `metadataBase` + Default-OG/Twitter/Robots/`title.template`; jede Page baut ihre eigene Metadata über den `pageMetadata({ locale, href, title?, description? })`-Helper aus `src/lib/seo/alternates.ts`, der `buildAlternates(locale, href)` über `next-intl`-`getPathname` wraped und `canonical` + `languages.{de,en,x-default}` korrekt mit Slug-Übersetzungen aus `routing.ts` füllt. Twitter-Card wird im Helper hartkodiert auf `summary_large_image`, weil ein object-level Override im Page sonst die Layout-Default verschlucken würde. Sitemap (`src/app/sitemap.ts`) liegt **außerhalb** `[locale]/`, weil Sitemaps site-weit sind; sie listet STATIC_HREFS × beide Locales mit `xhtml:link rel="alternate"` und ergänzt Blog-Slugs gracefully (über `isSupabaseConfigured()`-Gate, damit der Build ohne Supabase-Env nicht bricht — siehe ADR-31). OG-Image liegt unter `[locale]/opengraph-image.tsx` (eine Variante pro Locale, kein `generateImageMetadata` nötig); `ImageResponse` rendert OKLCH unzuverlässig, daher die Akzentfarbe als Hex `#2660d8` statt `oklch(0.55 0.16 250)` (siehe ADR-22). Top-Level Convention Files (`/icon`, optional `/apple-icon`, `/manifest`) müssen aus dem next-intl-Proxy-Matcher exkludiert werden, sonst werden sie auf `/<locale>/icon` redirected und brechen mit `InvariantError`. CI ist eine GitHub-Action mit lint/typecheck/build, **ohne Supabase-Env** — der Build prüft strukturell durch (graceful Fallback auf ComingSoonHero), Live-Daten-Validation passiert über Vercel-Preview-Deploys. |
| ADR-36 | 2026-05-06  | **Satori erlaubt in `ImageResponse` nur die CSS-Display-Werte `flex`, `block`, `contents`, `none`, `-webkit-box`** — `inline-block` führt zu HTTP 500 in Production | Satori (das Engine hinter `next/og`'s `ImageResponse`) ist eine eigenständige CSS-Implementation, kein Browser-CSS. `display: inline-block` wirft beim Rendering einen Pipe-Error (`failed to pipe response`, cause: `Invalid value for CSS property "display"`). Lokal mit `pnpm start` bekommt der Caller HTTP 200 mit Content-Type `image/png`, weil der Header geschrieben wird, **bevor** das Satori-Rendering startet — der Stream bricht dann mit Body-Fehler ab. Vercel meldet HTTP 500 mit `x-matched-path: /500`. Lehre: in jedem `ImageResponse`-Tree konsequent `display: "flex"` setzen (auch für leere Span-Akzente, Punkte, Spacer); Pixelgrößen über `width`/`height`. Generell für Satori-JSX: zwei Children im selben Container brauchen einen expliziten `flex`-Parent, sonst meckert Satori; `<br/>` und Inline-Text mit Geschwistern führen ebenfalls zu Problemen. |
| ADR-37 | 2026-05-07  | **View Transitions API über `experimental.viewTransition: true` + Reacts `<ViewTransition>`** statt manuelles `document.startViewTransition` | Next.js 16 hat das Feature offiziell hinter dem Experimental-Flag (Schema in `node_modules/next/dist/server/config-schema.js:316`, Doc unter `node_modules/next/dist/docs/01-app/02-guides/view-transitions.md`). Reacts `<ViewTransition>`-Component aktiviert ihre Animationen nur innerhalb von Transitions/Suspense/`useDeferredValue` — Next.js triggert eine Transition automatisch bei jeder Soft-Navigation, also reicht ein `<Link>` aus `@/lib/i18n/navigation`. Manuelles `document.startViewTransition` würde Reacts Transition-Lifecycle umgehen und mit GSAP-Animationen konkurrieren. Erstes Morph-Pair: PostCard-Cover ↔ PostArticle-Cover via `<ViewTransition name={`post-cover-${slug}`}>`. Sichtbar erst, sobald Posts ein `cover_image_url` haben. TypeScript braucht `/// <reference types="react/canary" />` (in `src/types/react-canary.d.ts`), weil das Symbol nur in `@types/react/canary.d.ts` deklariert ist; Runtime kommt aus Nexts gebundeltem `react`. CSS: globale Reduced-Motion-Regel auf `::view-transition-{old,new,group}(*)` in `globals.css`. |
| ADR-38 | 2026-05-07  | **Hero auf der Landing bleibt textbasiert** — keine Parallax-Animation auf den Text-Block, stattdessen konsolidierte Stagger-Konstante (`STAGGER=0.08`) + statischer dekorativer Akzent-Blob (`bg-[oklch(0.55_0.16_250/_0.10)] blur-3xl`) | Plan-Agent verglich drei Optionen: (a) `translateY`-Scrub auf den gesamten Hero-Text-Block, (b) parallaxer Akzent-Blob, (c) nur Reveal-Choreografie konsolidieren + statisches Element. (a) liest sich auf Apple-Niveau billig und kollidiert mit der Wort-Stagger-Animation in `RevealText`. (b) zieht in einer text-only-Hero die Aufmerksamkeit auf das Hintergrund-Element. (c) ist Apple-like minimal: Stagger-Delays kaskadieren Kicker→Title→Subtitle→CTA mit 80 ms-Schritten, der Blob ist subtil, statisch, decorativ. Sobald das echte Hero-Visual vom User geliefert ist, wird der Blob durch `<ParallaxImage>` ersetzt; die Stagger-Konstante bleibt. |
| ADR-39 | 2026-05-07  | **Layout-globaler `<ScrollTriggerRefresher />`** als Single-Listener auf `usePathname()`-Changes, statt `revertOnUpdate` pro `useGSAP` oder Per-Component-Listener | Soft-Navigation in App-Router triggert kein `load`-Event, also müssen ScrollTrigger-Positions nach jedem Routenwechsel neu berechnet werden, wenn sich Layout-Höhe oder Section-Positionen ändern. `revertOnUpdate` aus `@gsap/react` 2.1.2 reagiert nur auf Dependency-Changes innerhalb derselben Component-Instanz, nicht auf Route-Wechsel — falsches Tool. Der Refresher hängt einmal in `[locale]/layout.tsx` neben `NextIntlClientProvider`, ist Render-`null` und ruft nach `requestAnimationFrame` ein `ScrollTrigger.refresh()`, sodass der DOM-Layout-Pass des neuen Routes durch ist. Greift in keine bestehende `useGSAP`-Komponente ein, respektiert die existierende `registerScrollTrigger`-Lazy-Logik. |
